The question

Two Platforms. One Complex Signal.

Online restaurant reviews hold a detailed record of customer satisfaction. Yet the signal is rarely balanced: some ratings dominate, while the quiet minority is hardest for a model to recognize.

Review language also shifts between platforms. Wongnai and Google Maps carry different writing styles, rating habits, and review contexts. This project asks whether the way we handle class imbalance changes what a model can learn—and how well those lessons travel.

?

Research question

How well do models transfer between platforms, and do K-Means distance features improve Logistic Regression?

What the latest archive shows

English translation and cleaning columns (review_en, review_clean_en); F1 unigram TF-IDF, F2 unigram + bigram TF-IDF, and F3 MiniLM embeddings. Translation engine, model versions, hyperparameters, and training code were not supplied.

These exports differ from the proposed original-Thai PyThaiNLP workflow below. The native-Thai pipeline and K-Means hybrid remain proposed until matching outputs are available.

Prepare without leakage

Define fixed text-cleaning rules; remove empty/invalid reviews and exact duplicates, and check near-duplicates and cross-platform overlap before assigning splits. Keep duplicate groups in one partition; restaurant grouping is proposed where identifiers exist.

Split before fitting any learned transformation. Normalize noise and whitespace without discarding sentiment cues; tokenize Thai with PyThaiNLP (proposed: newmm). Tokenizer/package version, stop words, n-grams, and TF-IDF settings: To be confirmed.

Test the K-Means hybrid

TF-IDF → K-Means → distances to cluster centres. Concatenate those distances with the original TF-IDF features, then train Logistic Regression. Clusters are features, not sentiment labels; the number of clusters need not equal the sentiment-class count.

Compare with ordinary TF-IDF + Logistic Regression using identical splits, folds, metrics, tuning budgets, and imbalance settings. Choose cluster count and any distance scaling on training folds only. Improvement is a research question, not a promised result.

Fit on training data only

Fit TF-IDF, K-Means, any scaling, and oversampling only on the training portion, refitting inside each cross-validation fold. Apply fitted transformations to validation/test reviews without refitting. Keep test labels and test data untouched during model selection.

Proposed: stratified training-fold cross-validation with a fixed held-out test set and recorded seeds. Split ratios, fold count, grouping rules, and the source's existing test-set use: To be confirmed.

Control class imbalance

Compare no balancing against class weighting where supported (or documented sample weights). Treat SMOTE as a separate, conditional experiment: check minority examples per fold, neighbor settings, sparse-text geometry, and memory feasibility. Do not apply SMOTE to raw text or test data.

For hybrid runs, learn centroids from original training TF-IDF, form combined features, then apply any approved training-only resampling. Keep ordinary and hybrid imbalance conditions matched; document omitted or infeasible runs.

Separate evaluation settings

Within-platform: train and evaluate on disjoint reviews from the same platform. Cross-platform transfer: Google Maps external scores are supplied; the full source-training protocol is not documented. The original plan includes Wongnai → Google Maps and Google Maps → Wongnai, using source-trained vocabulary, centroids, and classifier with the same approved labels.

Do not fit or tune on the target test platform; exclude overlapping reviews from source training. Confirm completed directions, target holdout, and sample-size controls against the evaluation code. Report each direction separately.

Separate exploratory K-Means comparison

Additional local experiment, separate from your supplied Python outputs. A new JavaScript implementation uses weighted multinomial Logistic Regression, K-Means distance features, and a fixed SGD training budget. It does not reproduce the absent original notebook.

Same 7,999 historical test reviews; results were previously inspected, so this is exploratory
ModelAccuracyMacro-F1
Ordinary LR56.27%0.4537
LR + K-Means distances55.72%0.4490
Training-majority baseline63.92%0.2600

Hybrid minus ordinary Macro-F1: -0.0048. No improvement in this single run; this does not establish that K-Means features cannot help under other settings.

Seed 42; K=16 fixed in advance; balanced class weights; unigram + bigram TF-IDF capped at 20,000 features. Both arms select from the same three regularization values using a grouped validation holdout. Blank training rows, overlapping training texts, and repeated text/label pairs are excluded; the full historical test set is retained. One K-Means initialization, at most 25 iterations, and 25 SGD epochs are fixed budgets, not convergence claims.
